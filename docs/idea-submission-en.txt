1. PROBLEM STATEMENT ───────────────────────────────────────────────────────────

  Title: Bridging the Physical World with Blockchain through Real-World
         Treasure Hunts

  Problem:
  The physical world and blockchain remain disconnected. User interaction
  with blockchain today is limited to screens — trading, swapping, NFTs,
  DeFi — but nothing connects physical locations with digital assets.

  On the other hand, "treasure hunts" and "geocaching" exist offline, but:
  ❌ No economic incentive — rewards are physical prizes, not digital assets
  ❌ Centralized trust — relies entirely on the organizer
  ❌ Not scalable — requires third-party management
  ❌ Not transparent — no on-chain proof of who claimed what

  JELAJAH solves this by creating a treasure hunt marketplace that is:
  ✅ Trustless — rewards locked in Stellar Claimable Balances
  ✅ Decentralized — anyone can create a hunt
  ✅ Transparent — all events recorded on-chain
  ✅ Real economy — hunters earn XLM/USDC, not physical prizes

2. WHY STELLAR? ───────────────────────────────────────────────────────────────

  Stellar is the only blockchain that natively supports JELAJAH's use case
  without needing complex custom contracts:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ Stellar Feature     │ Why It Matters for JELAJAH                       │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Claimable Balances   │ Native escrow — funds held until conditions met.│
  │                      │ No need for a custom escrow contract.            │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Path Payments        │ Poster pays USDC, hunter in Indonesia receives  │
  │                      │ IDR via Anchor — 1 atomic transaction.          │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ ~$0.001 per tx       │ Viable for small hunts of $1.                   │
  │                      │ On Ethereum, gas > reward.                       │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Native multi-sig     │ Dispute resolution: 2-of-3 verifiers.           │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Anchor Protocol      │ Hunter in Indonesia withdraws to local bank     │
  │                      │ account seamlessly.                             │
  └──────────────────────┴──────────────────────────────────────────────────┘

  Anchor Integration:
  - Hunters in developing countries cash out to local bank accounts via
    Anchors (e.g., Bitazza in Southeast Asia)
  - Hiders deposit in XLM/USDC, hunters withdraw via Anchor
  - Path Payments handle atomic currency conversion

  Stack:
  - Frontend:  Next.js 16 + React 19 + TypeScript 5 + Tailwind 4 + shadcn/ui
  - Blockchain: Stellar (Soroban Contracts + Horizon API)
  - Database:  Supabase PostgreSQL (17 tables, realtime subscriptions)
  - Storage:   IPFS via Pinata
  - Map:       Mapbox GL JS
  - Wallet:    Freighter (Stellar Wallets Kit upcoming)

  Smart Contracts (5 deployed on Testnet):
  - hunt-factory:  Creates new hunt instances
  - hunt-instance: Per-hunt lifecycle: deposit, claim, verification, release
  - reputation:    XP, level, badges on-chain
  - dispute:       Multi-sig commit-reveal voting
  - quest-chain:   Multi-step quest with on-chain progress

  Data Flow:
  1. Hider creates hunt → upload photo to IPFS → call hunt-factory contract
     → reward locked in Claimable Balance → metadata stored in Supabase
  2. Hunter claims hunt → GPS verified → evidence photo → submit to contract
     → 24h timer → hider approves / auto-release / dispute
  3. Dispute → 3 verifiers commit-reveal vote → 2-of-3 decides

5. COMPLEXITY EVALUATION ─────────────────────────────────────────────────────

  Technical Challenges:

  A. GPS Verification On-Chain
     - GPS coordinates must be verified inside smart contract
     - Haversine distance calculation in Soroban (integer math, no floating
       point, no external libraries)
     - Anti-spoofing: GPS + photo timestamp + multi-sig combination

  B. Commit-Reveal Voting
     - Verifiers vote without seeing each other's votes (commit phase)
     - Hash-based: verifier commits hash(vote + salt)
     - Reveal phase: all votes revealed, validated against hashes
     - 2-of-3 threshold: requires quorum

  C. Claimable Balance Integration
     - Reward locked in Stellar Claimable Balance (native escrow)
     - Auto-release: if hider doesn't respond in 24h, hunter auto-claims
     - Dispute result determines fund flow

  D. Cross-Border Economics
     - Hunter in Indonesia: USDC reward → IDR via Anchor
     - Path Payments: single atomic conversion transaction
     - Anchor API: withdraw to bank account

  E. Real-Time GPS + Blockchain
     - Browser Geolocation API for real-time position
     - On-chain verification via contract call after submission
     - Anti-cheat: multi-factor location verification
