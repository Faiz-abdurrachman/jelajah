------------------------------------------------------------------------------
  1. PROBLEM STATEMENT
------------------------------------------------------------------------------

Real-world treasure hunts and location-based games exist today, but they all
face a fundamental trust problem: participants must trust the organizer to
actually pay the reward. There is no escrow, no dispute resolution, and no
transparent verification system.

Current problems:
  • Hiders (organizers) must be trusted to pay rewards — no guarantee exists
  • Hunters have no recourse if unfairly rejected
  • GPS spoofing and fake claims are hard to prevent without cryptographic proof
  • Dispute resolution is opaque and biased toward the platform
  • No way to create verifiable, location-based claims on-chain

JELAJAH solves this by creating a trustless, transparent ecosystem where
rewards are locked in Stellar Claimable Balances, GPS verification happens
on-chain, and disputes are resolved via multi-sig commit-reveal voting.

------------------------------------------------------------------------------
  2. WHY STELLAR?
------------------------------------------------------------------------------

Stellar is uniquely suited for this application:

  a) Claimable Balances (Native Escrow)
     Rewards are locked at hunt creation. The hider cannot withdraw them.
     The hunter can claim them only when conditions are met (approval or
     auto-release after 24h). No custom escrow contract needed — it's native.

  b) Micropayment Viability
     Stellar fees are ~Rp 1 (0.00001 XLM) per transaction. This makes it
     viable for small hunts (starting from Rp 10,000) where Ethereum gas
     would exceed the reward itself.

  c) Path Payments
     A hider deposits USDC, a hunter in Indonesia receives IDR — all in one
     atomic transaction via Stellar Anchors.

  d) Multi-sig Native
     Dispute resolution uses Soroban contracts with 2-of-3 verifier voting.
     Commit-reveal prevents vote collusion. Stellar's native multi-sig
     infrastructure supports this elegantly.

  e) Anchor Protocol
     Winners can cash out to local bank accounts via Stellar Anchors,
     bridging crypto to real-world fiat.

  f) Soroban Smart Contracts
     Custom logic for hunt lifecycle, reputation, quest chains, and dispute
     resolution — all on Stellar's WASM-based Soroban platform.

  4. TECHNICAL ARCHITECTURE
------------------------------------------------------------------------------

  FRONTEND (Next.js 16 + React 19 + TypeScript 5)
  ─────────────────────────────────────────────────
  • Mapbox GL JS for interactive map with hunt markers
  • shadcn/ui + Tailwind CSS 4 for responsive UI
  • Freighter Wallet integration for Stellar auth
  • IPFS (Pinata) for photo evidence storage

  SMART CONTRACTS (Rust + Soroban SDK 27)
  ─────────────────────────────────────────────────
  • hunt-factory: Creates hunt instances, emits events
  • hunt-instance: Full lifecycle (deposit → claim → verify → release)
  • reputation: XP, level, and badge management
  • dispute: Multi-sig commit-reveal voting with appeal
  • quest-chain: Multi-step sequential quests

  DATA FLOW
  ─────────────────────────────────────────────────
  Create Hunt:
    Hider inputs clue → Upload photo to IPFS → Hash clue + CID →
    Call hunt-factory.create_hunt() → Reward locked in Claimable Balance →
    Metadata stored in Supabase → Marker appears on map

  Claim Hunt:
    Hunter navigates to GPS location → GPS verified on-chain →
    Takes photo → Uploads to IPFS → Submits claim →
    24h timer starts → Hider approves OR auto-release

  Dispute:
    Hider rejects claim → 3 verifiers selected →
    Commit votes (hash) → Reveal votes →
    2-of-3 majority decides → Reward released or returned

  OFF-CHAIN (Supabase PostgreSQL)
  ─────────────────────────────────────────────────
  • Hunt metadata, user profiles, notifications
  • Realtime subscriptions for live map updates
  • 17 tables across all levels (L1-L7)

------------------------------------------------------------------------------
  5. COMPLEXITY EVALUATION
------------------------------------------------------------------------------

  HIGH COMPLEXITY AREAS:

  a) GPS Verification On-Chain
     • Converting GPS coordinates (lat/lng × 10^7) to Soroban i64/i128
     • Haversine distance calculation in no_std Rust environment
     • Anti-spoofing: GPS metadata from browser + photo timestamp +
       multi-sig verification

  b) Commit-Reveal Voting
     • Verifiers commit a hash of their vote + salt
     • After all commit, they reveal (vote, salt)
     • On-chain verification that hash(verifier, vote, salt) matches
     • Prevents vote copying and collusion

  c) Claimable Balance Integration
     • Native Stellar Claimable Balances as escrow
     • Must coordinate Soroban contract state with balance claims
     • Auto-release logic: 24h timer triggers contract-level release

  d) Quest Chain Sequencing
     • Multi-step quests where each step unlocks the next
     • GPS verification per step, photo evidence per step
     • Final step triggers reward claim

  e) Cross-Layer Architecture
     • On-chain: Soroban contracts for trustless logic
     • Off-chain: Supabase for metadata, IPFS for media
     • Indexer needed to sync contract events → database
     • Realtime sync between blockchain state and UI

------------------------------------------------------------------------------
  1. PERNYATAAN MASALAH
------------------------------------------------------------------------------

Permainan berburu harta karun di dunia nyata sudah ada, tapi semuanya punya
masalah kepercayaan fundamental: peserta harus percaya bahwa penyelenggara
benar-benar akan membayar hadiahnya. Tidak ada escrow, tidak ada resolusi
sengketa, dan tidak ada sistem verifikasi yang transparan.

Masalah saat ini:
  • Hider (penyelenggara) harus dipercaya untuk membayar — tidak ada jaminan
  • Hunter tidak punya jalur banding jika klaim ditolak secara tidak adil
  • GPS spoofing dan klaim palsu sulit dicegah tanpa bukti kriptografis
  • Resolusi sengketa tidak transparan dan bias ke platform
  • Tidak ada cara untuk membuat klaim berbasis lokasi yang terverifikasi on-chain

JELAJAH menyelesaikan ini dengan ekosistem trustless dan transparan di mana
hadiah dikunci di Stellar Claimable Balances, verifikasi GPS terjadi on-chain,
dan sengketa diselesaikan melalui pemungutan suara multi-sig commit-reveal.

------------------------------------------------------------------------------
  2. MENGAPA STELLAR?
------------------------------------------------------------------------------

Stellar sangat cocok untuk aplikasi ini:

  a) Claimable Balances (Escrow Native)
     Hadiah dikunci saat pembuatan hunt. Hider tidak bisa menariknya.
     Hunter bisa klaim hanya jika kondisi terpenuhi (approval atau auto-release
     setelah 24 jam). Tidak perlu kontrak escrow khusus — ini native.

  b) Mikropayment yang Viable
     Biaya Stellar ~Rp 1 (0,00001 XLM) per transaksi. Ini membuatnya viable
     untuk hunt kecil (mulai Rp 10.000) di mana gas Ethereum bisa melebihi
     nilai hadiah itu sendiri.

  c) Path Payments
     Hider deposit USDC, hunter di Indonesia terima IDR — semua dalam satu
     transaksi atomik melalui Stellar Anchors.

  d) Multi-sig Native
     Resolusi sengketa menggunakan kontrak Soroban dengan voting 2-of-3
     verifikator. Commit-reveal mencegah kolusi voting. Infrastruktur multi-sig
     native Stellar mendukung ini dengan elegan.

  e) Anchor Protocol
     Pemenang bisa cairkan ke rekening bank lokal melalui Stellar Anchors,
     menjembatani crypto ke fiat dunia nyata.

  f) Soroban Smart Contracts
     Logika khusus untuk siklus hidup hunt, reputasi, quest chain, dan resolusi
     sengketa — semuanya di platform WASM Soroban milik Stellar.

------------------------------------------------------------------------------
  5. EVALUASI KOMPLEKSITAS
------------------------------------------------------------------------------

  AREA KOMPLEKSITAS TINGGI:

  a) Verifikasi GPS On-Chain
     • Konversi koordinat GPS (lat/lng × 10^7) ke i64/i128 Soroban
     • Perhitungan jarak Haversine di lingkungan no_std Rust
     • Anti-spoofing: metadata GPS browser + timestamp foto +
       verifikasi multi-sig

  b) Voting Commit-Reveal
     • Verifikator commit hash dari vote + salt mereka
     • Setelah semua commit, mereka reveal (vote, salt)
     • Verifikasi on-chain bahwa hash(verifikator, vote, salt) cocok
     • Mencegah copy voting dan kolusi

  c) Integrasi Claimable Balance
     • Claimable Balance native Stellar sebagai escrow
     • Koordinasi state kontrak Soroban dengan klaim balance
     • Logika auto-release: timer 24 jam memicu rilis di level kontrak

  d) Urutan Quest Chain
     • Quest multi-langkah di mana setiap langkah membuka langkah berikutnya
     • Verifikasi GPS per langkah, foto bukti per langkah
     • Langkah terakhir memicu klaim hadiah

  e) Arsitektur Lintas-Layer
     • On-chain: Kontrak Soroban untuk logika trustless
     • Off-chain: Supabase untuk metadata, IPFS untuk media
     • Indexer diperlukan untuk sinkronisasi event kontrak → database
     • Sinkronisasi realtime antara state blockchain dan UI
